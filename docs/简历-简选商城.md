## 项目经历

### 简选商城 — 前后端分离电商系统 ｜ 个人项目 / 独立完成
**2026.09 – 2026.11**

技术栈：Spring Boot 3.5 · MyBatis-Plus 3.5 · MySQL 8 · JWT · BCrypt · Vue 3 + Vite

- 独立完成商品、购物车、订单三大模块的后端设计与开发，共 **25** 个 RESTful 接口，按 `controller / service / mapper / entity / dto` 分层，对外只暴露 VO 不直出实体，避免敏感字段泄露。
- 统一 `Result<T>` 返回体 + 全局异常处理：业务异常返回真实 HTTP 状态码（401/403/404/409），前端可直接按状态码分流，无需解析业务码判断错误类型。
- 基于 JWT + BCrypt 实现无状态登录，登录态经 ThreadLocal 在请求链路内传递并在请求结束时清理，避免线程复用导致的用户串号；自定义 `@AdminOnly` 注解配合拦截器反射校验，用声明式注解替代在每个管理端方法里重复写权限判断。
- 下单流程用 `@Transactional` 保证「扣库存 / 建订单 / 建明细 / 清购物车」的原子性，库存扣减采用 `UPDATE ... WHERE stock >= ?` 单条 SQL 原子更新，受影响行数为 0 即抛异常回滚，从数据库层面杜绝超卖；购物车数量累加同样把校验放在 SQL 的 WHERE 里，避免「先查后改」的并发窗口。
- 压测中发现同一秒内订单号随机后缀碰撞（240 单失败 2 单，与生日问题期望值 0.94 吻合），改用雪花 ID 生成订单号，复测 640 单零冲突；随后用 Python 多进程压测逐项排除连接池、SQL 控制台日志、客户端 GIL 三个伪瓶颈，确认写接口上限来自热点商品行锁（单商品 **145** QPS，分散到 20 个商品后 **506** QPS），并整理出库存分桶、Redis 预扣的优化路径。
