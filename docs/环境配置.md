### mock 与真实后端的切换

前端 `src/mock/index.js` 顶部有 `MOCK_AUTH` 开关：

```js
const MOCK_AUTH = false   // false = 认证走真实后端；true = 回到纯前端模式
```

`axios-mock-adapter` 的 `onNoMatch: 'passthrough'` **只对「完全没匹配到 handler」的请求生效**。只要某个 URL 注册过 handler，mock 就会拦下它，不会自动落到真实后端。所以关闭某个模块的 mock 时，必须显式写 `.passThrough()`——只把开关改成 `false` 是不够的，请求会被 mock 吞掉。当前状态：

| 模块 | 数据来源 | 说明 |
|---|---|---|
| 认证（注册/登录/当前用户） | ✅ 真实后端 | M1 |
| 商品 / 分类 | ✅ 真实后端 | M2，`MOCK_PRODUCT = false` |
| 购物车 | ✅ 真实后端 | M3，`MOCK_CART = false` |
| 订单（下单/列表/详情/取消/确认） | ✅ 真实后端 | M4，`MOCK_ORDER = false` |
| 管理后台（商品） | ✅ 真实后端 | M2，`@AdminOnly` 鉴权 |
| 管理后台（订单） | ✅ 真实后端 | M5，列表 + 发货 |

至此所有模块都已接入 Spring Boot，`src/mock/index.js` 里只剩「开关全部为 `true` 时」才会用到的假数据实现，正常运行时不参与。

新增后端模块后的切换动作：把对应 handler 包进 `if (MOCK_XXX)` 并置 `false`，**一次只切一个模块**，避免页面一次性全坏。

### 联调踩过的坑

**1. HTTP 状态码必须是真状态码**
后端 `GlobalExceptionHandler` 早期返回「HTTP 200 + body.code=401」，导致前端 axios 的 error 分支永远不触发，token 过期后不会跳登录页。已改为 `ResponseEntity.status(...)`，让 HTTP 层语义正确。

**2. `/api/xxx` 不存在时返回 401 而不是 404**
拦截器在路由匹配之前就检查 token，未登录访问任何 `/api/**` 都是 401。这是正确行为（不泄漏接口是否存在）。要测 404 handler 得用非 `/api` 路径，例如 `/nonexistent-page`。

**3. mock 自己造的 token 和真实 JWT 不兼容**
`mock/index.js` 的 `currentUser()` 加了对真实 JWT 的解析（base64url 解 payload 取 `sub`/`role`），否则 admin 登录后进管理后台会被 401 踢回登录页。
