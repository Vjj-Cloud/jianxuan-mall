## 5. Spring Boot 配置（写 application.yml 时用）

```yaml
# 口令与 JWT 密钥不直接写在这里，放 application-local.yml（已被 .gitignore 排除）
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/jianxuan_mall?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: mall
    password: ${DB_PASSWORD}        # 真实值在 application-local.yml
    driver-class-name: com.mysql.cj.jdbc.Driver

jwt:
  secret: ${JWT_SECRET}             # 至少 32 字节，真实值同样在 application-local.yml
```

两个占位符都没有默认值，缺配置时启动会直接报 `Could not resolve placeholder`。首次搭建：

```bash
cd backend/src/main/resources
cp application-local.yml.example application-local.yml
# 填入数据库密码和 jwt.secret 后即可启动
```

## 6. Redis（订单超时取消依赖）

订单超时取消用的是 Redis ZSet 延迟队列，**没有 Redis 时后端能启动**（连接懒加载），但一调用下单接口就报连接失败。

### 安装位置与版本

| 项 | 值 |
|---|---|
| 目录 | `D:\redis` |
| 版本 | Redis 5.0.14（Windows 移植版，2022 年构建） |
| 可执行文件 | `D:\redis\redis-server.exe`、`redis-cli.exe` |
| 服务名 | `Redis`，启动类型**自动**（开机自启） |
| 生效的配置文件 | `D:\redis\redis.windows-service.conf` |

> `redis.windows.conf` 是手动起进程用的，**服务读的是 `redis.windows-service.conf`**。
> 改配置一定改带 `-service` 的那个，改错文件会「改了没生效」。

### 常用命令

```bash
net start Redis               # 启动（已在跑会提示「服务已经启动」）
net stop Redis                # 停止
sc query Redis                # 查状态（或用 Get-Service Redis）
D:/redis/redis-cli.exe ping   # 返回 PONG 即正常
```

也可以用 Redis 自带的服务命令（免管理员）：
`D:\redis\redis-server.exe --service-start` / `--service-stop`

**不要再用 `redis-server.exe redis.windows.conf` 手动起进程**——服务和手动进程都抢 6379，后来的那个必然启动失败，报 `Creating Server TCP listening socket *:6379: bind: No error`（这个报错文案有坑，实际原因是端口被占用）。

### 配置文件的三处改动（为什么改）

| 配置 | 原值 | 现值 | 原因 |
|---|---|---|---|
| `appendonly` | `no` | **`yes`** | 只开 RDB 的话，两次快照之间宕机会丢掉延迟任务，那些订单永远等不到取消。AOF `everysec` 最多丢 1 秒 |
| `dir` | `./` | **`D:/redis`** | 服务方式启动时工作目录不是安装目录，相对路径会把 `dump.rdb` / `appendonly.aof` 写到 `C:\Windows\System32` 下 |
| `logfile` | `server_log.txt` | **`D:/redis/redis-service.log`** | 同上，避免日志落到系统目录 |

数据文件：`D:\redis\dump.rdb`（RDB 快照）、`D:\redis\appendonly.aof`（AOF）。

### 验证配置真的生效

`CONFIG GET` 返回的是运行时实际值，比看配置文件可靠：

```bash
D:/redis/redis-cli.exe config get appendonly    # 应为 yes
D:/redis/redis-cli.exe config get dir           # 应为 D:\redis
D:/redis/redis-cli.exe info persistence | grep aof_enabled   # aof_enabled:1
```

持久化实测（写完重启服务，数据还在才算数）：

```bash
D:/redis/redis-cli.exe set k v
D:/redis/redis-server.exe --service-stop
D:/redis/redis-server.exe --service-start
D:/redis/redis-cli.exe get k    # 仍返回 v
```

### 换机器怎么装

1. 把整个 `D:\redis` 拷到目标机器同名目录（配置文件里的绝对路径是 `D:/redis`，换路径要同步改 `dir` / `logfile`）
2. 管理员权限执行：`D:\redis\redis-server.exe --service-install D:\redis\redis.windows-service.conf --loglevel notice`
3. `net start Redis`
4. `redis-cli ping` 确认 `PONG`

服务通过 `Service Control Manager` 注册，无管理员权限时 `--service-install` 可能成功但 `Start-Service` 会报「无法打开计算机上的服务」，此时用 `--service-start` 即可。

## 7. 前后端联调

### 启动顺序（MySQL 必须在跑）

```bash
# 1) 后端（8080）
cd <项目根>/backend
export JAVA_HOME="/d/vj-demo/jdk-17"
export PATH="/d/vj-demo/apache-maven-3.9.16/bin:$PATH"

# 2) 前端（5173，另开一个终端）
```

> 那是 shell 里有 `SERVER__PORT` 之类的环境变量被 Spring Boot 宽松绑定成了 `server.port`。
> 显式覆盖即可：`SERVER__PORT=8080 mvn spring-boot:run`。在 IDEA 里点运行不受影响。

> 接口文档从 Knife4j 换成了 springdoc 官方 Swagger UI：Knife4j 4.5.0 绑死 springdoc 2.3.0，在 Spring Framework 6.2 上打开文档会 500（`NoSuchMethodError`）；把 springdoc 升到 2.8.9 后 Knife4j 又调不到新 API。为了不降级 Spring Boot，只能换 UI。文档页右上角 Authorize 可填 token 直接调试。

### mock 与真实后端的切换

前端 `src/mock/index.js` 顶部有 `MOCK_AUTH` 开关：

```js
const MOCK_AUTH = false   // false = 认证走真实后端；true = 回到纯前端模式
```

`axios-mock-adapter` 的 `onNoMatch: 'passthrough'` **只对「完全没匹配到 handler」的请求生效**。只要某个 URL 注册过 handler，mock 就会拦下它，不会自动落到真实后端。所以关闭某个模块的 mock 时，必须显式写 `.passThrough()`——只把开关改成 `false` 是不够的，请求会被 mock 吞掉。当前状态：

| 模块 | 数据来源 | 说明 |
|---|---|---|
| 认证（注册/登录/当前用户） | ✅ 真实后端 | M1 |
| 商品 / 分类 | ✅ 真实后端 | M2，`MOCK_PRODUCT = false` |
| 购物车 | ✅ 真实后端 | M3，`MOCK_CART = false` |
| 订单（下单/列表/详情/取消/确认） | ✅ 真实后端 | M4，`MOCK_ORDER = false` |
| 管理后台（商品） | ✅ 真实后端 | M2，`@AdminOnly` 鉴权 |
| 管理后台（订单） | ✅ 真实后端 | M5，列表 + 发货 |

至此所有模块都已接入 Spring Boot，`src/mock/index.js` 里只剩「开关全部为 `true` 时」才会用到的假数据实现，正常运行时不参与。

新增后端模块后的切换动作：把对应 handler 包进 `if (MOCK_XXX)` 并置 `false`，**一次只切一个模块**，避免页面一次性全坏。

### 联调踩过的坑

**1. HTTP 状态码必须是真状态码**
后端 `GlobalExceptionHandler` 早期返回「HTTP 200 + body.code=401」，导致前端 axios 的 error 分支永远不触发，token 过期后不会跳登录页。已改为 `ResponseEntity.status(...)`，让 HTTP 层语义正确。

**2. `/api/xxx` 不存在时返回 401 而不是 404**
拦截器在路由匹配之前就检查 token，未登录访问任何 `/api/**` 都是 401。这是正确行为（不泄漏接口是否存在）。要测 404 handler 得用非 `/api` 路径，例如 `/nonexistent-page`。

**3. mock 自己造的 token 和真实 JWT 不兼容**
`mock/index.js` 的 `currentUser()` 加了对真实 JWT 的解析（base64url 解 payload 取 `sub`/`role`），否则 admin 登录后进管理后台会被 401 踢回登录页。
